# Как внести вклад в руководство по стилю

## Как предложить изменение

1. Если правило нужно обсудить, создайте Issue с меткой `proposal` и опишите проблему,
   пример нарушения и предлагаемое правило.
2. Если изменение очевидно (опечатка, уточнение примера), сразу создайте ветку и Pull
   Request.
3. Имя ветки: `docs/<краткое-описание>` для разделов, `fix/<описание>` для исправлений,
   `ci/<описание>` для настройки сборки.

## Требования к коммитам

Сообщения коммитов оформляются по спецификации Conventional Commits:

```text
<тип>(<область>): <описание в повелительном наклонении>
```

Допустимые типы:

- `docs` — новый или изменённый раздел руководства;
- `fix` — исправление ошибки в тексте или примере;
- `style` — форматирование без изменения смысла;
- `ci` — изменения в GitHub Actions;
- `build` — изменения в `mkdocs.yml` и зависимостях;
- `chore` — прочие служебные изменения.

Примеры:

```text
docs(accessibility): добавить раздел о доступности текста
fix(terminology): исправить определение термина «доска»
ci: добавить проверку Vale в конвейер
```

Описание пишется со строчной буквы, без точки в конце, не длиннее 72 символов.

## Процесс ревью

1. Откройте Pull Request в `main` и заполните шаблон описания.
2. Дождитесь, пока CI пройдёт: markdownlint, Vale, `mkdocs build --strict`.
3. Назначьте одного ревьюера. Ревьюер отвечает в течение двух рабочих дней.
4. Ревьюер оставляет комментарии трёх видов: «Замечание» (блокирует слияние),
   «Предложение» и «Вопрос».
5. Автор исправляет замечания отдельными коммитами и отвечает на каждый комментарий.
6. После одобрения автор выполняет слияние способом Squash and merge.

## Как запустить локальную сборку

```bash
git clone https://github.com/Tttnya/style-guide-project.git
cd style-guide-project
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
mkdocs serve
```

Сайт откроется по адресу <http://127.0.0.1:8000>. Проверки перед коммитом:

```bash
npx markdownlint-cli2 "docs/**/*.md"
vale docs
mkdocs build --strict
```

## Как добавить новый раздел

1. Создайте файл `docs/<имя-раздела>.md` — имя латиницей, через дефис.
2. Начните файл с заголовка первого уровня и вводного абзаца.
3. Пронумеруйте правила с префиксом раздела (например, `Д1`, `Д2`) и укажите уровень
   обязательности.
4. Добавьте раздел в блок `nav` файла `mkdocs.yml`.
5. Если появились новые термины, добавьте их в `docs/terminology.md`.
6. Запустите локальную сборку и откройте Pull Request.
