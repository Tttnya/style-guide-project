# Руководство по стилю документации TaskFlow

Руководство описывает правила, по которым команда TaskFlow пишет и оформляет документацию
веб-сервиса для управления задачами. Руководство распространяется на пользовательскую
документацию, справку по REST API, инструкции администратора и заметки о выпуске.

## Кому адресовано руководство

- Техническим писателям, которые готовят документацию.
- Разработчикам, которые описывают API и пишут README.
- Ревьюерам, которые проверяют изменения в документации.

## Как пользоваться руководством

1. Перед началом работы прочитайте разделы «Принципы и голос» и «Язык и стиль».
2. При подготовке нового документа возьмите шаблон из раздела «Шаблоны».
3. Перед отправкой Pull Request запустите линтеры: часть правил проверяется автоматически.
4. Если правило не покрывает вашу ситуацию, используйте приоритет источников, приведённый
   ниже, и предложите дополнение через Pull Request.

## Приоритет источников

Если правила противоречат друг другу, действует следующий порядок:

1. Настоящее руководство.
2. Глоссарий TaskFlow (раздел «Терминология»).
3. Правила русской орфографии и пунктуации.
4. Google Developer Documentation Style Guide — для вопросов, которых нет в руководстве.

## Уровни обязательности

Каждое правило имеет маркер обязательности (таблица 1).

Таблица 1 – Уровни обязательности правил

| Маркер | Значение |
|---|---|
| Обязательно | Нарушение блокирует слияние Pull Request |
| Рекомендуется | Отступление допустимо, если автор объяснил причину в PR |
| Допускается | Вариант на усмотрение автора |
