# Оформление текста

## Формат исходных файлов

- Документация пишется в Markdown (CommonMark и расширения MkDocs Material).
- Имена файлов — латиницей, строчными буквами, слова через дефис: `create-project.md`.
- Длина строки в исходнике — не более 100 символов.
- Файл заканчивается пустой строкой.

## Списки

- Маркированный список — для элементов без порядка, нумерованный — для последовательных
  шагов.
- Если пункт — законченное предложение, он начинается с прописной буквы и заканчивается
  точкой.
- Если пункты — фрагменты одного предложения, они начинаются со строчной буквы,
  разделяются точкой с запятой, последний заканчивается точкой.
- В списке не меньше двух пунктов. Вложенность — не более двух уровней.

## Таблицы

- Таблица используется для сравнения объектов по одинаковым признакам.
- У каждой таблицы есть строка заголовков.
- Перед таблицей — вводное предложение, которое ссылается на неё.
- Ячейки не оставляются пустыми: вместо пустоты ставится «—».

## Выделение

Таблица 1 – Способы выделения текста

| Что выделяем | Как |
|---|---|
| Элемент интерфейса | Полужирный |
| Новый термин при первом упоминании | Курсив |
| Код, путь, имя файла, значение | Моноширинный |
| Клавиши | `Ctrl+S` |

Не используйте выделение для эмоционального акцента, подчёркивание и ЗАГЛАВНЫЕ буквы.

## Примечания

Используйте блоки admonition. Допустимы только четыре типа.

Таблица 2 – Типы примечаний

| Тип | Когда использовать |
|---|---|
| `note` | Дополнительная информация, без которой задачу можно решить |
| `tip` | Способ сделать работу быстрее или удобнее |
| `warning` | Действие может привести к ошибке или неудобству |
| `danger` | Действие приведёт к потере данных и необратимо |

В одном разделе — не больше двух примечаний подряд.

## Ссылки

- Текст ссылки описывает цель: «см. [Как создать проект](structure.md)», а не «нажмите
  [здесь](structure.md)».
- Внутренние ссылки — относительные пути к файлам `.md`.
- Внешние ссылки ведут на официальные источники.
