# Интерфейс, код и API

## Элементы интерфейса

- Названия элементов интерфейса пишутся так, как они выглядят на экране, и выделяются
  полужирным: нажмите **Сохранить**.
- Кавычки для элементов интерфейса не используются.
- Путь по меню записывается через знак «>»: **Настройки > Уведомления > Почта**.
- Глаголы действий: «нажмите» — кнопка, «выберите» — пункт списка или меню, «введите» —
  поле ввода, «включите» / «отключите» — переключатель, «установите флажок» — флажок.

## Примеры кода

- Каждый блок кода имеет указание языка, например `bash` или `json`.
- Пример должен запускаться без изменений, кроме значений-заполнителей.
- Заполнители пишутся прописными латинскими буквами через подчёркивание:
  `YOUR_ACCESS_TOKEN`, и поясняются после блока кода.
- Приглашение командной строки (`$`) в примерах не ставится, чтобы команду можно было
  скопировать.
- Вывод команды приводится в отдельном блоке.

## Описание конечной точки API

Каждая конечная точка описывается по единой схеме:

1. Заголовок — назначение: «Создать задачу».
2. Метод и путь: `POST /api/v1/tasks`.
3. Краткое описание в одном предложении.
4. Таблица параметров: имя, тип, обязательность, описание.
5. Пример запроса.
6. Пример ответа и таблица кодов ответа.

Пример таблицы параметров приведён в таблице 1.

Таблица 1 – Пример таблицы параметров конечной точки

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `title` | string | Да | Название задачи, до 200 символов |
| `assignee_id` | integer | Нет | Идентификатор исполнителя |
| `due_date` | string | Нет | Срок в формате ISO 8601 |
