# Процесс Docs as Code

## Жизненный цикл изменения

1. Создайте ветку от `main` с именем `docs/<краткое-описание>`.
2. Внесите изменения в Markdown-файлы.
3. Запустите локальную проверку: `markdownlint-cli2 "docs/**/*.md"`, `vale docs`,
   `mkdocs build --strict`.
4. Сделайте коммит в формате Conventional Commits.
5. Откройте Pull Request и заполните шаблон описания.
6. Дождитесь успешной проверки CI и одобрения одного ревьюера.
7. Выполните слияние: сайт развёртывается на GitHub Pages автоматически.

## Автоматические проверки

Таблица 1 – Автоматические проверки

| Инструмент | Что проверяет |
|---|---|
| markdownlint | Синтаксис Markdown, заголовки, списки, длину строки |
| Vale | Стиль: канцеляризмы, запрещённые термины, слова-паразиты |
| `mkdocs build --strict` | Битые ссылки, отсутствующие файлы в навигации |

## Ревью

Ревьюер проверяет то, что не умеют линтеры:

- соответствие типу документа и шаблону;
- точность инструкций — ревьюер выполняет шаги сам;
- понятность для читателя без контекста;
- корректность терминов, которые не попали в правила Vale.
